# 批量生成视频功能策划文档

状态：主体已实现。项目创建、素材分析、创意策划（标准 5–20 条 / 量产最多 1000 条）、参考图池与程序匹配、人工审核、创意编辑与重新匹配、批量提交（单模型失败切换 / 多模型并发）、服务端持久队列、重试与统计、后台配置均已上线；待验证与未实现项见 `docs/content/docs/progress/pending-test.mdx`（弱匹配 Top 3–5 模型复核、提交预算/幂等限流、多项目公平调度、千条级压测等尚未实现）。

范围：新增一个独立的“批量生成视频”模块，不改动画布、创作页、图片/视频工作台和任务中心的原有流程。目标规模为单项目最多 1000 条视频。

## 1. 结论摘要

1. 主导航新增“批量生成视频”，项目、创意、审核、生成、重试、统计全部在该模块内完成。
2. 一个项目对应一个产品；不同产品/新 SKU 必须新建项目。
3. 所有项目统一从“标准批量”开始，不提供创建时的模式选择。完成标准验证后才解锁“大批量铺量”。
4. 创意采用模板化量产，允许卖点和角度重复，允许同质化；只拦截完全重复和合规/产品一致性问题。
5. 参考图是项目级共享资产，创意只引用；描述在资产级维护一份，创意可追加用法说明。
6. 参考图数量由硬上限、覆盖目标和预算共同约束；模型只能建议缺什么，不能决定生成到多少张停止。
7. 参考图匹配以程序为主：结构化需求 + 标签过滤 + 打分；模型只复核弱匹配的 Top 3–5 张。
8. 第一版不使用向量数据库和 embedding 模型；精确重复用内容哈希，语义匹配后续再引入 pgvector 和小型文本 embedding。
9. 视频模型是否允许批量生成，开关放在模型配置中，默认关闭；批量视频的全局参数放在独立后台菜单。
10. 只有视频生成实际使用的参考图允许生成 OSS 副本；上传素材、产品图、文档、策划原图、生成视频、缩略图等一律保存在服务器本地。
11. 同一素材按内容哈希去重，同一用户重复上传相同文件时复用已有资源，不重复上传、不重复占用容量。
12. 生成任务由后端持久队列调度，离开页面不中断；服务重启后恢复。
13. 批量提交支持两种模式：一次一个模型（按可用度自动选择和切换）和一次多个模型（同一创意同时产出多版本）。
14. 重试按模型策略执行：同一模型达到失败阈值后切换模型；单个创意的总尝试次数为“勾选模型数 × 每模型尝试次数”。

## 2. 核心概念

| 概念 | 定义 |
| --- | --- |
| 项目 | 一个产品对应的容器，包含产品档案、素材批次、参考图库、创意轮次和生成任务 |
| 产品档案 | 产品名称、受众、调性、卖点、禁用词、视觉规范 |
| 素材批次 | 每次上传的一组图片/文档；保留历史，不覆盖旧批次 |
| 卖点 | 从素材图片或文档提取的产品卖点，带证据来源和使用次数 |
| 参考图库 | 项目级共享参考图资产，带描述、标签、版本、使用次数和状态 |
| 创意轮次 | 一次“生成 N 条创意”的批次，记录模式、数量、参数和素材快照 |
| 创意 | 一条视频策划，包含文案、卖点、钩子、视频提示词、图片需求和参考图引用 |
| 生成槽位 | 创意 × 模型的可执行单元；模式 b 下同一创意有多个槽位 |
| 尝试 | 某个槽位的一次任务执行；用于统计重试成功/失败和模型切换 |
| 标准验证 | 项目解锁大批量前必须完成的小批量全审和视频验收 |
| 放量 | 标准验证通过后，项目获得大批量生产资格 |

## 3. 用户流程

### 3.1 主流程

```text
批量生成视频（主导航）
  → 项目列表
  → 新建项目（1 步：只填项目名称）
  → 项目工作台
      → 生成标准创意
      → 审核标准创意（全审）
      → 提交标准视频生成
      → 标准验收
      → 解锁大批量铺量
      → 大批量生成创意
      → 模板审核 + 抽检
      → 批量提交生成
      → 队列运行与监控
  → 追加创意（原素材 / 新素材批次）
      → 新轮次 → 审核 → 再提交
```

### 3.2 项目状态

```text
draft
  → analyzing
  → standard_generating
  → standard_reviewing
  → standard_validating
  → mass_unlocked
  → mass_generating
  → running
  → completed
```

失败或暂停不改变项目阶段，只更新运行状态和统计。

## 4. 页面流程

### 4.1 项目列表

路由：`/batch-video`

每行项目（表格）展示：

- 产品名/项目名
- 阶段：草稿、分析中、标准创意生成中、标准审核中、标准验收中、可放量、量产中、已完成
- 创意数、已通过数、已生成视频数、失败数
- 参考图池使用量，例如 `18 / 50`
- 最近更新时间
- 操作：打开、删除

主按钮：新建项目。

删除规则：仅项目归属用户可删除；二次确认后级联删除素材批次、卖点、参考图、创意、生成任务、尝试记录与验收快照，不可恢复；存在进行中的分析、策划或生成任务时拒绝删除，需先取消未开始项并等待运行中的任务结束。

筛选：全部、标准验证中、可放量、量产中、已完成。

### 4.2 新建项目（1 步）

不提供“标准批量/大批量”选择，所有项目默认进入标准模式。

**创建页只做一件事：填写项目名称并创建。**

- 项目名称必填；产品名称可选（留空时使用项目名称）。
- 素材、文档、卖点、视频参数与模型都不在创建页填写，创建后进入项目工作台按顺序完成。

**项目内按步骤继续：**

1. 上传素材并分析：上传图片/视频与卖点文档，或直接粘贴文本；批次名称可选，留空自动使用当天日期；数字命名的图片按数值升序保存。上传成功后立即自动开始分析，图片同时进入项目共享参考图库。多张图片按后台并行数（默认 10）同时执行，每次模型调用仍只附一张图片，单张结果写入参考图资产；分析进度在前台逐张展示，完成前不可关闭，只能中止。
2. 项目设置（可选）：视频时长、画面比例、标准验证创意数（5–20）。文本策划模型、读图模型和参考图生成模型均由服务端按后台优先级即时挑选，项目不保存模型。
3. 生成创意 → 人工审核 → 提交生成。
- 上传即分析，不需要额外的确认弹窗；服务端每次按后台优先级挑选可用文本模型（有图片时只接受支持读图的模型），不写回项目设置。
- 自动分析启动失败时（例如没有可用模型），素材仍保留，同一步内可手动重新分析并提示先完善项目设置。

### 4.3 项目工作台

路由：`/batch-video/:projectId`

顶部固定区：

```text
产品名   [阶段]   创意 1000 · 通过 820 · 成功 610 · 失败 12
[追加创意] [审核 180] [提交生成] [暂停/继续] [更多]
```

阶段与按钮规则：

| 阶段 | 可用操作 |
| --- | --- |
| 草稿/分析中 | 修改素材、参数、重新分析 |
| 标准创意生成中 | 查看进度、暂停 |
| 标准审核中 | 逐条/批量审核、改文案、重生成参考图 |
| 标准验收中 | 查看标准视频、确认验收 |
| 可放量 | 解锁大批量、继续标准补量 |
| 量产中 | 查看进度、暂停/继续、重试失败、追加新轮次 |
| 已完成 | 查看产物、追加创意、导出列表 |

页签：

1. **概览**：漏斗、成功/失败、费用、预计剩余时间、存储占用、异常提醒。
2. **创意**：创意列表、筛选、批量操作、单条详情。
3. **审核**：模板审核、抽检、异常项、批量通过/驳回。
4. **生成任务**：队列、运行、成功、失败、重试统计。
5. **素材与档案**：素材批次、产品档案、卖点、参考图库。

### 4.4 概览页

展示：

- 创意漏斗：已生成 → 已审核 → 已提交 → 成功视频
- 今日/累计成功、失败、重试成功/失败
- 按模型统计：尝试、成功、失败、失败率
- 费用、预计剩余时间、吞吐量
- 存储占用：本地、OSS 参考副本
- 异常：模型不可用、余额不足、预算达到上限、磁盘不足、失败率异常

### 4.5 创意页

- 服务端分页 + 虚拟滚动，不一次渲染 1000 条。
- 筛选：轮次、模板、卖点、参考图匹配状态、审核状态、生成状态、重复标记。
- 展示：参考图缩略图、标题、文案摘要、卖点、钩子、匹配状态、审核状态、生成状态。
- 批量操作：通过、驳回、删除、重新匹配参考图、重新生成参考图。
- 单条抽屉：完整文案、视频提示词、图片需求、引用参考图及其描述、来源素材、相似创意、生成历史。
- 布局：宽屏为左图右文，窄屏单列；参考图保持比例，不长期遮挡内容。

### 4.6 审核页

- **标准模式**：100% 人工审核，不允许抽检放行。
- **大批量模式**：模板审核 + 抽检 5%–10% + 异常项处理。
- 顶部显示：待审、抽检、异常、已通过、已驳回。
- 支持按模板/卖点分组批量通过。
- 单条操作：通过、驳回、编辑文案、编辑视频提示词、重新匹配参考图、重新生成参考图。
- 驳回必须选择原因，可选“文案不合格、图片不匹配、合规风险、产品不一致、完全重复”。
- 审核通过是提交视频生成的唯一入口。

### 4.7 生成任务页

- 顶部统计：排队、运行、成功、失败、重试中。
- 按模型分组：尝试、成功、失败、重试成功、重试失败、平均耗时。
- 任务表：创意、模型、槽位、尝试次数、当前状态、失败原因、产物、操作。
- 操作：单条重试、批量重试失败项、暂停队列、取消未开始项。
- 支持按轮次、模型、状态、失败原因筛选。
- 点击产物直接预览视频；点击任务查看 attempt 历史和模型切换链。

### 4.8 素材与档案页

包含三块：

1. **素材批次**
   - 每批：批次名、上传时间、图片数、文档数、分析状态、视觉版本。
   - 新增批次：上传 → 并行分析（每张单独调用并落库，默认同时 10 张）→ 差异确认 → 合并。再次分析默认只补跑未成功分析的图片；全部完成后按钮变为“重新分析”，确认后才重跑全部素材。
   - 图片文件名（去掉扩展名）为纯数字时，按数值从小到大保存和展示；非数字命名保持上传顺序。
   - 删除：支持删除单张素材、删除整批和清空全部。已被创意引用的素材拒绝删除；同一资源仍被其他批次使用时保留参考图与文件；批次内图片和文档都清空后自动移除批次。
   - 分析、策划或生成运行期间禁止调整素材，对应完成或中止后再操作。
   - 素材变化后项目分析标记为 `stale`，需要重新分析后才能继续策划。
2. **产品档案**
   - 产品名、受众、调性、视觉规范、禁用词。
   - 卖点列表：标准表述、证据来源、置信度、使用次数、状态。
3. **参考图库**
   - 图片网格：缩略图、描述、标签、来源、版本、状态、使用次数。
   - 顶部：`参考图池 18 / 50`、覆盖率、预算使用。
   - 操作：生成缺口、补充参考图、停用、查看引用创意。

### 4.9 关键弹窗

**生成创意**

- 数量
- 选择模板或全部模板
- 轮次名称
- 是否先试跑 3–5 条
- 解锁大批量后，弹窗出现“标准补量 / 大批量铺量”两个入口

**追加创意**

- 方式一：原素材追加，沿用产品档案和参考图池
- 方式二：新素材追加，上传新批次 → 增量分析 → 选择“新旧混合 / 仅用新素材” → 生成新轮次
- 数量、模板、试跑选项
- 新素材、新模板、新模型先走标准验证，再允许量产

**提交生成**

1. 选择创意，默认全部已通过
2. 勾选允许批量生成的视频模型
3. 选择模式：
   - a. 一次提交一个模型：按优先级选一个先跑，失败切换
   - b. 一次提交多个模型：每个模型各生成一版
4. 展示预估任务数、总费用、预计时间
5. 余额、预算、存储不足时阻止提交
6. 提交后任务进入 `submitted`，不立即调用模型；在任务面板点击“开始生成”或设置定时后，才释放到调度队列

### 4.10 1000 条页面规则

- 所有列表服务端分页。
- 长列表使用虚拟滚动。
- 统计由服务端聚合，不在浏览器遍历全部记录。
- 批量操作支持“全选当前筛选结果”，不默认全选全部。
- 页面关闭不取消任务；重新打开恢复进度。
- 提交前显示任务数、费用、预计时间。
- 运行中显示暂停、继续、取消未开始项和失败重试。
- 大批量模式默认突出进度、费用、失败率，不突出逐条精修。

## 5. 素材与卖点

### 5.1 素材要求

- 至少 1 张素材图片。
- 卖点文档可选，仅支持 `.md` / `.txt`，或直接粘贴文本。
- 第一版不支持 PDF、Word 解析。
- 支持图片、视频素材；分析模型是否支持视频参考由模型能力决定。

### 5.2 卖点来源

- 只有图片：视觉模型从图片提取产品类别、外观卖点、使用场景、目标人群。
- 图片 + 文档：文档提供明确卖点，图片提供视觉证据。
- 只有文档：允许，但提示“缺少产品图，参考图可能出现外观偏差”。
- 项目记录卖点来源：图片、文档、混合。

### 5.3 卖点管理

- 卖点合并同义表述，维护 canonical 卖点。
- 每个卖点记录：标准表述、证据来源、首次出现批次、置信度、使用次数、状态。
- 新素材批次提到同一卖点时合并证据，不重复创建卖点。
- 新素材与旧档案冲突时标记“待确认”，人工决定是否更新。
- 卖点可以重复使用，不做唯一性限制。

### 5.4 新素材批次

流程：

1. 上传新批次；批次名可选，留空自动生成“当天日期 + 素材批次序号”。
2. 增量分析，输出：
   - 新增卖点
   - 已有卖点的新证据
   - 新场景/新人群
   - 视觉变化（包装、颜色、logo）
   - 与旧档案冲突
3. 人工确认合并范围。
4. 选择“新旧混合”或“仅用新素材”。
5. 视觉变化明显时，先走标准验证，再允许放量。
6. 旧创意保留原素材批次快照，不回溯修改。

## 6. 参考图库

### 6.1 共享模型

参考图属于项目，不属于单条创意。

参考图资产字段：

- 资源 ID
- 内容哈希
- 标题
- 描述
- 图片生成提示词
- 标签：产品、卖点、场景、角度、风格、比例
- 来源：上传素材、AI 生成、人工修改
- 状态：待确认、已通过、已停用
- 版本号
- 使用次数、最近使用时间
- 创建时间

创意保存：

- `reference_asset_ids`
- 每条引用的版本号
- 创意级用法说明 `reference_caption`

描述分两层：

- 资产级描述：这张图是什么，只存一份。
- 创意级描述：这条创意为什么选它、怎么用。

提交生成时，将“图片 + 资产描述 + 创意用法”合成最终提示词，并快照到任务输入。之后图库改图或改描述，不影响已提交或重试任务。

### 6.2 版本与引用

- 参考图不覆盖更新，新增版本。
- 新创意默认引用最新已通过版本。
- 旧创意继续引用旧版本，除非人工切换。
- 图片被创意引用时不能删除。
- 删除前检查创意、任务和生成槽位引用。

### 6.3 数量控制

同时设置四个值：

| 配置 | 作用 | 默认建议 |
| --- | --- | --- |
| 覆盖目标 | 软目标：覆盖卖点、场景、角度 | 按项目配置 |
| 项目参考图上限 | 硬上限 | 标准模式 20，大批量模式 50 |
| 单轮新增上限 | 防止一次补图过多 | 20 |
| 参考图预算 | 费用硬上限 | 按项目配置 |

停止条件：

- 覆盖目标完成。
- 达到项目上限。
- 达到费用预算。
- 模型建议补图时必须人工确认，且不能超过上限。
- 项目只能调低上限，不能超过后台上限。

模型只负责建议“还缺哪些画面”，不决定“生成到多少张停止”。

### 6.4 创意图生成与匹配

创意图生成是独立阶段，不和创意文案生成混在一起。

流程：

```text
创意生成
  → 输出结构化图片需求
  → 程序硬过滤：产品、状态、比例、标签、禁用项
  → 程序打分：卖点、场景、角度、风格、使用次数
  → 强匹配：直接分配图库图片
  → 弱匹配：模型复核 Top 3–5 张
  → 无匹配：标记缺图
  → 按需求分组，批量生成新图
```

图片需求字段：

- 卖点
- 场景
- 角度
- 风格
- 画面比例
- 必须出现的产品元素
- 禁止出现的元素
- 图片生成提示词

判断职责：

| 判断 | 执行方 |
| --- | --- |
| 产品、状态、比例、标签硬条件 | 程序 |
| 卖点/场景/角度打分 | 程序规则或简单文本相似度 |
| 语义复核 | 模型，仅弱匹配 Top 3–5 |
| 是否缺图 | 程序按阈值 |
| 是否生成新图 | 程序按缺图队列和上限 |
| 生成多少张 | 后台/项目配置硬上限 |

### 6.5 Token 控制

- 创意输出结构化需求，不把整段创意和整个图库交给模型。
- 用“卖点 + 场景 + 角度 + 风格 + 比例”生成需求指纹。
- 同一指纹只判断一次，结果缓存。
- 缺图按需求分组，相同需求只生成一张图，分配给多条创意。
- 模型只看 Top 3–5 张候选缩略图和简短描述。
- 强匹配默认信任程序；弱匹配、低分、高风险才调用模型。
- 模型复核比例可配置，建议 5%–10%。

### 6.6 第一版不引入向量

- 不使用向量数据库。
- 不使用 embedding 模型。
- 精确重复用 SHA-256/感知哈希。
- 语义匹配后续可选：
  - PostgreSQL + pgvector。
  - 小型中文文本 embedding（如 bge-small-zh）。
  - 仅在需要按画面相似度找图时再引入 CLIP/SigLIP。
- 当前参考图池只有 20–50 张，标签 + 规则 + 暴力相似度足够。

后续如果启用 embedding：

- 优先用 PostgreSQL + pgvector，不新增独立向量数据库。
- 优先做文本 embedding（资产描述与创意需求），不先做图像 CLIP。
- 小模型可部署在 NAS 的 x86 环境；ARM 或低内存 NAS 不建议本地跑，可改用托管 embedding API 或继续使用标签匹配。
- 图像 CLIP/SigLIP 只用于“按画面相似度找图”，不作为第一版需求。

## 7. 创意生成

### 7.1 由谁策划

- 由文本/视觉大模型策划。
- 不使用视频模型策划。
- 不使用云端 Agent 做常规批量策划。
- 文本策划模型由后台优先级决定，不在项目或向导中手动选择；管理员调整优先级或新增模型后即时影响下一次任务。
- 分析与策划可以使用同一个模型，也可以分开配置。
- 策划模型必须具备视觉能力，因为需要读取产品图片。

### 7.2 生成方式

- 用户只填写数量，系统内部拆批。
- 每批 50–100 条，规则填槽 + 少量 LLM 改写。
- 模板库：每个产品准备 5–10 个创意模板，例如痛点、对比、开箱、场景、口播。
- 槽位：卖点 × 钩子 × 场景 × CTA × 文案变体。
- 同质化允许；卖点和角度可以重复。
- 只拦截完全重复、合规风险和产品明显不一致。
- 不把覆盖矩阵、新颖度评分作为硬门槛。
- 覆盖率只作为统计和建议，不作为放量前置条件。

### 7.3 创意输出

每条创意至少包含：

```json
{
  "title": "标题",
  "sellingPoint": "卖点",
  "hook": "前 3 秒钩子",
  "copywriting": "口播/字幕文案",
  "videoPrompt": "视频运动与镜头提示词",
  "imageRequirement": {
    "scene": "场景",
    "angle": "角度",
    "style": "风格",
    "aspectRatio": "9:16",
    "requiredElements": ["产品"],
    "forbiddenElements": []
  },
  "imagePrompt": "参考图生成提示词",
  "durationSeconds": 8,
  "aspectRatio": "9:16"
}
```

### 7.4 质量检查

必须检查：

- 结构完整。
- 文案、提示词、时长、比例合法。
- 合规和禁用词。
- 产品名、包装、颜色、logo 不出现明显偏差。
- 完全重复拦截。

不做硬性拦截：

- 同质化。
- 卖点重复。
- 角度重复。
- 文案风格接近。

完全重复判定：

1. 组合指纹：卖点 + 钩子 + 场景 + 形式 + 人群 + 风格。
2. 文案相似度：标题、钩子、正文。
3. 参考图相似度：内容哈希/感知哈希。
4. 组合完全相同或文案高度相似时打回重写。

同卖点、不同钩子/场景/形式的创意允许存在。

### 7.5 模型调用与修复

- 严格 JSON 输出。
- JSON 不合法时用一次修复提示词。
- 修复仍失败则该批失败，可单独重试。
- 单批失败不影响整个项目。
- 创意生成任务由后端队列执行，页面可关闭。

## 8. 审核

### 8.1 标准模式

- 100% 人工审核。
- 不接受抽检放行。
- 审核通过后才允许提交标准视频。

### 8.2 大批量模式

- 模板审核：先确认创意模板和参考图池。
- 抽检：默认 5%–10%，可配置。
- 异常项：完全重复、合规风险、产品一致性异常、低分匹配。
- 支持按模板/卖点分组批量通过。
- 支持全审、抽检、自动放行三种模式；铺量默认抽检。
- 自动放行也必须通过合规和完全重复检查。

### 8.3 审核操作

- 通过。
- 驳回并选择原因。
- 编辑文案。
- 编辑视频提示词。
- 重新匹配参考图。
- 重新生成参考图。
- 重新生成该条创意。

## 9. 标准验证与放量门槛

### 9.1 统一入口

- 所有项目从标准模式开始。
- 新建项目不出现模式选择。
- 大批量铺量不是创建选项，而是完成标准验证后解锁的项目能力。

### 9.2 标准验证条件

默认同时满足：

1. 标准创意数量达到阈值，默认 10 条，可配 5–20。
2. 标准创意 100% 人工审核。
3. 每条标准创意至少成功生成 1 条视频。
4. 标准视频成功率不低于阈值，默认 80%。
5. 所有准备用于量产的模板都经过验证。
6. 所有准备用于量产的视频模型都至少成功生成 1 条标准视频。
7. 参考图池版本和素材批次已确认。
8. 人工确认可以放量。

后台可调整阈值，但服务端必须执行。

### 9.3 解锁

满足条件后，项目出现“解锁大批量铺量”按钮。

解锁时记录快照：

- 已验证模板 ID 和版本
- 已验证模型 ID
- 参考图池版本
- 素材批次版本
- 产品档案版本
- 操作人和解锁时间

### 9.4 重新验证

| 变化 | 处理 |
| --- | --- |
| 原素材追加、同模板 | 保持已放量，可直接量产 |
| 新素材批次 | 先跑 5–10 条标准验证，再放量 |
| 新包装/视觉明显变化 | 必须重新标准验证 |
| 新模板 | 至少 1–2 条标准验证 |
| 新视频模型 | 该模型至少成功 1 条标准视频 |
| 修改卖点/合规规则 | 建议重新抽检，严重时锁回标准模式 |

### 9.5 服务端强制

“大批量提交”接口必须校验：

- 项目已解锁。
- 模板在验证快照内。
- 模型在验证快照内。
- 参考图池版本匹配。
- 素材批次和产品档案版本匹配。
- 未解锁或快照不匹配直接拒绝。

不能只靠前端隐藏按钮。

## 10. 视频模型与提交模式

### 10.1 模型开关

- 模型配置中新增“允许用于批量视频”，默认关闭。
- 只有开启该开关的视频模型才会出现在批量提交的模型选择器中。
- 模型选择器显示“支持批量”徽标；未开启的模型不显示或置灰。
- 开关是应用层授权，不代表上游支持一次请求多视频。
- 开启后仍然是一个创意对应一个或多个独立任务。
- 图片分析失败时项目进入 `awaiting_decision`，前台显示失败原因并让用户选择继续剩余图片或中止；可选择记住本次选择，下次失败不再询问。
- 每个渠道模型（不限视频）都带通用“调用优先级”（`capabilityConfig.priority`，默认 50，1–10000）；批量视频的模型列表、候选顺序和调度队列按该优先级从高到低。旧配置只有 `video.batchGeneration.priority` 时读取回退到该字段。

### 10.2 两种提交模式

用户从允许批量生成的模型中勾选 1 到 N 个。

**模式 a：一次提交一个模型**

- 勾选模型作为候选池，按模型优先级从高到低排序。
- 系统先跑优先级最高的模型。
- 同一时间一个创意只有一个活跃模型。
- 失败达到阈值后切换下一个候选模型。

**模式 b：一次提交多个模型**

- 每个勾选模型同时提交同一创意。
- 同一创意可能产出多个模型版本。
- 每个模型一个生成槽位。
- 费用按“创意数 × 模型数”计算。
- 创意只要至少一个槽位成功即算成功；部分失败显示“部分成功”。

### 10.3 可用度排序

模式 a 的模型选择顺序：

1. 未在该创意上耗尽尝试次数。
2. 后台配置的通用模型优先级（`capabilityConfig.priority`，默认 50，越大越先调用）。
3. 同等优先级按模型前台排序和名称稳定排序。

全部不可用时进入排队，不直接判失败。模式 b 的调度队列同样先取 `model_priority` 高的任务。

### 10.4 提交校验

- 创意已审核通过。
- 模型已开启批量视频。
- 模型在标准验证快照内。
- 模式 b 的模型数不超过配置上限。
- 创意数不超过项目/后台上限。
- 预算、余额、存储容量足够。
- 服务端返回预估任务数和总费用。

## 11. 重试与模型切换

### 11.1 尝试次数

- 每个模型最多尝试次数默认 2 次，含首次。
- 该值在后台“批量视频设置”中可配置。
- 如果业务口径是“首次之外再重试 2 次”，把每模型尝试次数配成 3。
- 单个创意总尝试次数 = 勾选模型数 × 每模型尝试次数。
- 例如勾选 3 个模型、每模型 2 次，总上限 6 次。
- 每个创意独立计算尝试预算。
- 本文的“可用模型数”按本次勾选的候选模型数计算；如果业务口径是“全部已开启批量的模型数”，需要单独配置，避免把未勾选模型也计入重试预算。

### 11.2 同模型重试

- 复用原任务 ID。
- 记录新的 attempt。
- 保留任务与创意/槽位的归属。

### 11.3 跨模型切换

- 创建新任务。
- 任务 ID 会变化，但仍归属同一项目、同一创意、同一生成槽位。
- 记录切换链：原模型、失败原因、新模型、attempt 编号。

### 11.4 模式 a

- 当前模型失败达到阈值 → 标记该模型对该创意已耗尽 → 切换到下一个可用候选模型。
- 成功即停止。
- 全部模型耗尽 → 创意失败。

### 11.5 模式 b

- 每个模型一个槽位，独立重试。
- 某槽位模型耗尽后，可切换到“尚未为该创意成功产出的候选模型”。
- 不切换到已经成功的模型，避免重复版本。
- 创意至少一个槽位成功即成功。
- 全部槽位失败才算创意失败。
- 部分成功在统计中单独展示。

### 11.6 自动重试耗尽后

推荐：

- 自动重试严格停在总尝试上限。
- 用户可手动“重新提交”，作为新的重试轮次，单独计数、单独确认费用。
- 后台可关闭手动重试，形成绝对上限。

该口径需要在实现前确认。

### 11.7 不自动重试的情况

- 内容审核类错误不自动重试，沿用现有任务中心规则。
- 参数错误、资源缺失、余额不足不自动重试。
- 余额恢复后可由用户手动重试。

### 11.8 统计

项目维度：

- 创意总数、已通过、成功、部分成功、失败
- 总尝试次数、总费用

创意维度：

- 变体数、尝试次数、切换模型次数、当前状态

模型维度：

- 尝试数、成功数、失败数
- 重试成功数、重试失败数
- 平均耗时

槽位/尝试维度：

- attempt 编号、模型、任务 ID、状态、错误、开始/结束时间
- 是否自动切换

## 12. 任务运行模式

### 12.1 持久队列

- 提交后写入 `submitted`，不立即进入调度；手动开始或定时到点后转为 `waiting`。
- 不一次性创建 1000 个任务。
- 调度器按并发槽位和模型优先级逐步创建任务。
- 队列和 attempt 持久化到数据库。
- 服务重启后恢复。

### 12.2 调度

- 遵守用户活动任务上限。
- 遵守全局 Worker 并发和渠道并发。
- 优先级：素材分析 → 创意生成 → 参考图生成 → 视频生成。
- 多项目之间轮转，避免大批量饿死其他项目。
- 相同需求分组处理。
- 创建失败不直接标记创意失败，下一轮继续。

### 12.3 页面独立性

- 离开页面不中断任务。
- 页面只负责提交和展示。
- 重新打开项目时拉取最新状态。
- 不需要浏览器保持 SSE 连接才能继续执行。

### 12.4 控制

- 暂停：停止创建新任务，运行中的任务继续。
- 继续：恢复队列。
- 取消未开始项。
- 停止整批：可选，需确认。
- 失败率异常时可自动暂停并提示。

### 12.5 吞吐

粗略估算：

| 有效并发 | 单条耗时 | 1000 条约需 |
| --- | --- | --- |
| 5 | 3 分钟 | 10 小时 |
| 20 | 3 分钟 | 2.5 小时 |
| 50 | 3 分钟 | 1 小时 |

模式 b 勾选 3 个模型时，任务数、时间和费用按 3 倍计算。

## 13. 存储策略与内容去重

### 13.1 存储白名单

| 用途 | 存储位置 |
| --- | --- |
| 视频生成任务实际引用的参考图副本 | 允许 OSS |
| 上传的素材图片、产品图 | 强制本地 |
| md/txt 卖点文档、分析文本 | 强制本地/数据库 |
| 策划生成的参考图原图 | 强制本地 |
| 生成的视频、缩略图、播放副本 | 强制本地 |
| 分析结果、策划 JSON、审核记录 | 数据库 |

如果本地存储能通过 `CANVAS_PUBLIC_BASE_URL` 提供公网 HTTPS 访问，视频参考图也可以完全不放 OSS。

项目服务器容量足够，不因为容量压力使用 OSS；OSS 仅用于“上游视频模型必须通过公网读取参考图”的技术需要。

### 13.2 拦截点

1. 批量视频专用上传入口必须带 `purpose`。
2. 非 `video_reference` 用途强制 `forceLocal=true`。
3. 客户端传入 OSS 目标时忽略或拒绝。
4. 批量视频任务 metadata 带存储策略，任务媒体落盘、恢复、渲染都强制本地。
5. 只有视频参考图解析路径允许写 OSS 副本。
6. 服务端在写入前再次校验 purpose，越权写入报错。

### 13.3 与全局设置的关系

- 全局“生成结果存储位置”继续服务其他模块。
- 批量视频模块生成结果强制本地，不受全局 OSS 开关影响。
- 批量视频的 OSS 只用于派生参考副本。

### 13.4 内容哈希去重

- 上传时计算 SHA-256。
- `Resource.ContentHash` 新增字段。
- 建立 `(user_id, content_hash)` 唯一索引。
- 同一用户重复上传相同字节，返回已有 resource ID。
- 文件名不同也按内容去重。
- 并发重复上传由唯一约束兜底。
- 去重按用户隔离，不跨用户复用，避免权限问题。
- 同一素材被多个创意、多个项目引用时只存一份。
- 创意和任务只保存 resource ID，不按 URL/路径重新上传。
- 生成的视频/图片不做用户级内容去重，除非用于完全重复检查。

### 13.5 本地原图与 OSS 参考副本

- 同一逻辑资源可以有一个本地原图和一个 OSS 参考副本。
- 用 `resource_storage_variants` 记录副本。
- 唯一键：resource + purpose + provider + bucket + content hash。
- 同一图片被 100 条视频引用时，只生成一份 OSS 副本。
- 删除素材时检查本地原图和 OSS 副本的引用计数。
- 引用计数包含创意、生成槽位、任务和参考图库。

### 13.6 验证

- OSS 开启/关闭时，上传产品图都落本地。
- 生成视频、缩略图、播放副本始终本地。
- 只有视频参考图可能出现在 OSS。
- 同一文件上传两次只产生一个存储对象。
- 同一参考图被多个创意引用时 OSS 只有一份副本。
- 并发重复上传不产生两条资源记录。
- 页面显示“已复用现有素材”。

## 17. 权限、安全、计费

### 17.1 权限

- 所有项目、素材、参考图、创意、任务都校验当前用户归属。
- 管理员配置只在后台接口。
- 不能依赖前端隐藏按钮。
- 跨用户资源引用拒绝。
- 批量提交、重试、解锁都做服务端校验。

### 17.2 安全

- 固定服务端提示词，文档和素材作为数据，不执行其中指令。
- 创意 JSON 严格校验字段、数量、长度。
- 文档文本设置长度上限。
- 不使用任意 URL 作为参考图来源。
- 参考图资源必须是当前用户拥有且状态可用。
- 日志不记录密钥、Cookie、完整文档正文。
- 任务输入不包含内嵌媒体，必须先上传资源。

### 17.3 计费

- 分析、创意、参考图、视频都走现有任务计费。
- 批量提交前显示每条和总预估费用。
- 余额、预算不足阻止提交。
- 每个任务独立计费。
- 模式 b 费用按模型数翻倍。
- 价格变化时以实际任务扣费为准，记录实际费用。
- 批量模块不绕过现有报价和扣费。

### 17.4 限流

- 提交、重试、生成参考图接口使用现有任务创建限流。
- 调度器不受请求限流影响，但遵守活动任务上限和渠道并发。
- 防止重复点击和重复提交，提交接口幂等。

## 18. 1000 条规模设计

### 18.1 生成

- 用户只填数量，系统内部每批 50–100 条。
- 规则填槽 + 少量 LLM 改写，不逐条创意推理。
- 相同图片需求分组，避免每条生成参考图。
- 参考图池 20–50 张循环使用。

### 18.2 审核

- 标准验证阶段全审。
- 大批量阶段模板审核 + 抽检。
- 支持按模板/卖点批量通过。
- 异常项单独处理。
- 不做 1000 条逐条人工审核。

### 18.3 执行

- 持久队列，按槽位逐步创建任务。
- 暂停、继续、取消未开始项。
- 失败重试和模型切换自动化。
- 失败原因聚合。
- 页面关闭不中断。

### 18.4 数据库

- 生产使用 PostgreSQL。
- 本地开发可使用 SQLite。
- 队列领取、统计聚合、分页查询必须考虑两种数据库。
- 不使用一次性全表加载。
- 大量写入使用批量插入。
- 关键索引见 14.7。

### 18.5 页面

- 服务端分页 + 虚拟滚动。
- 统计接口聚合。
- 不一次渲染 1000 张卡片。
- 批量操作只作用于当前筛选结果。
- 长任务显示进度、预计剩余时间、暂停按钮。素材分析使用前台逐张进度窗，完成前不可关闭、只能中止；创意策划使用带百分比、阶段和运行时间的进度窗，可转后台或中止。中止分析保留素材、已完成图片结果与已生成卖点，中止策划保留已完成创意。生成任务列表显示整体进度条。

### 18.6 存储与费用

- 1000 条视频按单条 5–20MB 估算，约 5–20GB；本地存储需预检磁盘余量。
- OSS 只保存参考副本，不保存成品视频。
- 单项目预算上限和每日限额。
- 预算或磁盘达到阈值时暂停队列并提示。

### 18.7 压测节奏

1. 先用 20–50 条跑通模板、审核、队列、存储。
2. 再用 200 条压测并发、失败率、重试和费用统计。
3. 最后放开到 1000 条，并开启预算和存储保护。

## 19. 非目标

- 独立向量数据库。
- embedding 模型。
- 图像 CLIP/SigLIP 匹配。

- 上游一次请求返回多个视频。
- 自动发布到外部平台。
- 自动绕过人工审核。
- 复用画布批次状态。
- 修改画布、创作页、图片/视频工作台、任务中心的原有流程。
- 音频走 OSS。
- 把生成的视频或图片放到 OSS。

## 23. 待确认项

以下口径在实现前需要最终确认：

1. “同一模型失败两次”按总尝试 2 次（含首次）还是首次之外再重试 2 次；当前设计默认总尝试 2 次，可通过每模型尝试次数配置调整。
2. 模式 b 失败槽位是否允许切换到“尚未成功的模型”；当前设计允许，以保证尽量凑满变体，但不产生重复成功版本。
3. 自动重试耗尽后是否允许手动重新提交；当前设计允许作为新轮次，单独计数、单独确认费用，后台可关闭。
4. 标准验证默认 10 条、成功率 80%、覆盖全部模板和模型；这些值是否合适。
5. 只有文档或只有名称时是否允许创建项目；当前设计允许只填名称创建，之后在项目内补充素材，缺少产品图会影响外观描述与参考图匹配。
6. 解锁大批量的操作人：项目负责人还是仅管理员。
7. 生产环境是否统一使用 PostgreSQL；SQLite 仅用于本地开发和压测前验证。
8. “可用模型数”按本次勾选的候选模型数，还是按全部已开启批量的模型数计算重试总上限。
9. 参考图池默认上限（标准 20、大批量 50）是否符合实际素材规模。
